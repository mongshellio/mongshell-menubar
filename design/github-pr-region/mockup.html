GitHub PR 영역 목업

mongshell-menubar 의 단일 status item 안에 두 번째 영역을 두고, Claude 사용량과 GitHub PR 을 각각 호버·클릭하는 구성입니다. 모든 수치는 샘플이며, 색·치수는 Design/Palette.swift 와 현재 뷰의 값을 그대로 썼습니다.

리뷰 요청 행·섹션과 주황 점의 옛 의미는 #51 에서 바뀌었다 — 현재 사양은 docs/architecture.md § 4.

A. 메뉴바

왼쪽은 지금 그대로의 Claude 영역, 세로 헤어라인 뒤가 GitHub 영역입니다. GitHub 영역은 PR 글리프 · 신호등 점 · 처리할 PR 수. 2배 확대는 점검용이고, 아래 1배가 실제 크기입니다.

A1 · GitHub 끔 (현재와 동일)

설정이 꺼져 있으면 메뉴바·팝오버·설정 어디에도 흔적이 없습니다 (원칙 2).

A2 · 켬 · 처리할 것 없음

숫자 없이 글리프 + 초록 점. "내가 할 일이 없다" 를 숫자 0 보다 조용하게 말합니다.

A3 · 켬 · 3건, 그중 CI 실패 있음

숫자 = 리뷰 요청받은 PR + 내 PR 중 막힌 것. 점 = 내 PR 에 막힘(충돌·CI 실패·변경 요청)이 있으면 빨강, 리뷰 요청만 있으면 주황, 없으면 초록.

A4 · openclaw·서버 신호와 함께

기존 신호등 스택은 Claude 영역 안에 그대로 남고, GitHub 영역은 그 오른쪽입니다. 폭 증가분은 헤어라인 포함 약 46pt.

A5 · 라이트 메뉴바

글리프·숫자는 .secondary/.primary 로 상태바 배경을 따르고, 점은 색이 곧 정보라 고정입니다.

구현 메모
  • status item 은 하나입니다. PassthroughHostingView 에 트래킹 영역을 두 개 걸고, 클릭은 커서 위치를 두 영역의 사각형과 대조해 판정합니다.
  • PR 글리프는 SF Symbol arrow.triangle.pull, 점 크기 7pt 는 openclaw 점과 같습니다. 글리프·점·숫자 순서는 발자국+점 패턴의 연장입니다.

행 전체가 클릭 대상이고 (강조된 #45 행이 hover 상태) 클릭하면 브라우저에서 PR 을 엽니다. 마지막 줄이 GitHub 의 체크 목록입니다. 실패·진행중·건너뜀이 하나라도 있으면 검사를 전부 펼쳐 어느 것이 막혔는지 보이고, 전부 통과한 PR 은 "검사 N개 통과" 한 칩으로 접습니다. 진행중 점은 느리게 깜빡입니다. 칩 끝의 회색 시간은 소요시간입니다. 완료된 검사는 걸린 시간으로 고정되고, 진행중 검사는 시작부터 지금까지의 경과 시간이 열려 있는 동안 1초마다 올라갑니다 (위 목업에서도 흐릅니다). 접은 칩의 시간은 가장 늦게 끝난 검사까지의 총 소요시간입니다. 라인 diff 는 넣지 않습니다. ⋯ 메뉴: 새로고침 · GitHub 에서 열기 · 설정….

갱신 정책과 한도
  • 백그라운드 3분 (설정에서 1~10분) — 사용량 폴링과 같은 간격. 메뉴바 숫자·점과 호버 요약은 이 값을 씁니다. 호버는 갱신을 일으키지 않습니다.
  • 팝오버를 열 때 즉시 1회 — openclaw 섹션이 클릭 시 refreshNow() 를 부르는 것과 같은 방식.
  • 열려 있고 진행중 검사가 있으면 30초 — 경과 시간이 흐르는 동안 상태가 따라오게. 닫거나 진행중이 없어지면 3분으로 복귀.
  • 한 번의 갱신 = GraphQL 요청 1회 — 세 검색(리뷰 요청·내 PR·최근 머지)을 alias 로 묶고 각 PR 의 statusCheckRollup.contexts 까지 받습니다. 요청당 약 10 포인트, 3분이면 시간당 약 200 포인트. 한도는 토큰당 시간당 5,000 포인트이며 무료 계정도 같습니다.
  • 잔량 표시 — 같은 요청에 rateLimit { cost remaining resetAt } 를 함께 받아 푸터에 "API 잔량 4,812 / 5,000" 로 보여주고, 잔량이 바닥에 가까우면 사용량 폴링과 같은 지수 백오프로 주기를 늘립니다.
  • 소요시간의 출처 — Check Run(Actions·Vercel 등 GitHub App)은 startedAt/completedAt 이 있어 계산됩니다. 옛 방식 Commit Status 는 createdAt 뿐이라 시간을 비웁니다. 대기 중(QUEUED)도 비웁니다.

D. 배지 어휘

E. 합의가 필요한 지점

  1. 영역 경계 표시. 세로 헤어라인(위 목업) vs 간격만 두기 vs 기존처럼 "·" 점. 헤어라인이 "두 앱" 느낌에 가장 가깝습니다.
  2. 숫자의 뜻. 리뷰 요청 + 내 PR 중 막힌 것 (목업). 대안: 리뷰 요청만, 또는 열린 내 PR 전체.
  3. 점의 뜻. 빨강 = 내 PR 막힘, 주황 = 내 리뷰 대기, 초록 = 없음. 제안서의 "리뷰 요청 + 할당 이슈" 배지 대신 PR 만 셉니다.
  4. 클릭 시 강조. status item 이 하나라 클릭 팝오버가 열린 동안 Claude·GitHub 영역이 함께 강조됩니다 (Decision #8 후속 #39 와 같은 수용). 이게 싫으면 두 번째 status item 으로 가야 하고, 그러면 Decision #5 개정이 필요합니다.
  5. 호버 요약 두 줄. 리뷰 요청 / 내 PR + 막힌 첫 이유(실패한 검사 이름). 최근 머지는 호버에 넣지 않았습니다.
  6. 검사 줄. 라인 diff 대신 체크별 진행 상황과 소요시간. 하나라도 통과가 아니면 전부 펼치고, 전부 통과면 한 칩으로 접습니다. 진행중 경과 시간은 팝오버가 열린 동안 1초마다 올라갑니다. 대안: 항상 펼치기.
  7. 갱신 주기. 백그라운드 3분(1~10분 설정), 팝오버 열 때 즉시, 열림 + 진행중 검사면 30초. 제안서의 기본 5분을 3분으로 당겼습니다.
  8. 팝오버 섹션. 리뷰 요청 → 내 PR → 최근 머지 7일 → 푸터(API 잔량·갱신 시각). 이슈 섹션은 1차 범위 밖.
  9. 설정. "GitHub 표시" 토글, 토큰 상태(gh 자동 / PAT 입력), 갱신 주기(기본 3분·1~10분), 레포 숨기기. 이 목업에는 없고 developer 단계에서 기존 설정창 섹션 패턴을 따릅니다.
